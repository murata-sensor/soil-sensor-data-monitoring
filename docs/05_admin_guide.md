# 05. 管理者ガイド

Registry スプレッドシートの 5 つのシート（`sources` / `users` / `acl` / `theme` / `layouts`）で
アクセス制御と表示を管理します。イベント注釈は各データソースのスプレッドシートに `events` シートとして配置します。
ダッシュボードにログインして `/admin` を開けば画面から編集できますが、Registry スプレッドシートを直接編集しても OK です。

管理画面は、設定を読み込んだときの内容と、保存時点の内容を照合します。
その間に別の操作で設定が変わっていた場合は、古い内容で上書きせず「保存されていません」と表示します。
編集中の内容は画面に残ります。「再読み込み」はその編集内容を破棄するため、内容を確認してから実行してください。
管理 API と画面は対応する新しい版をセットで更新し、更新後は画面を開き直してください。

同じアカウントのログイン証明が更新されただけでは、未保存の入力を再読み込みで上書きしません。
ログアウトや別アカウントへの切り替えでは、画面内の未保存入力を引き継ぎません。
遅れて届いた通信結果が、前の利用者の表示設定を画面へ戻さないようにしています。
ただし、保存中のログアウトは Google 側で始まった書き込みを取り消すものではありません。
保存が完了したか不明な場合は、再ログイン後に最新の設定を読み込んで確認してください。

---

## 0. アクセス制御の整理（よく勘違いされるところ）

3 つの表が **3 つの異なる役割** を持っています:

| シート | 役割 |
| --- | --- |
| `users` | 「**このメールアドレスはログインできる/できない**」と「**ロール (admin / viewer)**」だけを決める |
| `sources` | 「**どんなデータ源がシステムに存在するか**」をカタログする |
| `acl` | 「**どの user がどの source を見られるか**」を 1 件ずつ許可する |

**間違いやすい点**: `users.enabled=TRUE` にしても、それは「ログインだけは通る」という意味で、
viewer ロールのユーザーは **`acl` に行を入れない限り 1 つもデータが見えません**（画面のソース選択ドロップダウンが空になる）。

`admin` ロールのユーザーだけは acl をスキップして全 `enabled` ソースを見られます。

### 管理者の交代

管理画面から `users` を保存するときは、実際に管理操作できる人を少なくとも1人残す必要があります。
`role=admin`・`enabled=TRUE` に加え、Google 側の `ADMIN_ALLOWED_EMAILS` にも登録された人が対象です。
最後の1人を削除・無効化・閲覧者に変更する保存や、全員を消す保存は拒否します。

1. Google 側の `ADMIN_ALLOWED_EMAILS` に新しい管理者のメールを追加する。今の管理者は残す。
2. `users` に新しい管理者を `admin`・`TRUE` で登録する。
3. 新しい管理者のアカウントでログインし、管理画面で読み書きできることを確認する。
4. 確認できてから、必要に応じて以前の管理者の権限や許可リストを変更する。

これは管理画面からの保存に対する保護です。Google の表や許可リストを直接変更する場合は、
同じ条件を満たす管理者を必ず残してください。

## 1. シートの書き方リファレンス

### 1-1. `users` シート

| 列 | 例 | 意味 |
| --- | --- | --- |
| `email` | `you@example.com` | Google アカウントのメール（小文字推奨） |
| `role` | `admin` または `viewer` | `admin` は全データ + `/admin` 画面アクセス。`viewer` は acl 許可分のみ |
| `enabled` | `TRUE` / `FALSE` | `FALSE` でログイン自体を拒否 |

同じメールは1行だけ登録してください。前後の空白と大文字・小文字を除いて同じメールが複数行あると、
管理・閲覧 API ともその利用者を拒否します。`email`・`role`・`enabled` の列もそれぞれ1列だけ必要です。
管理画面からの保存では重複を拒否します。既存の重複で管理画面を使えない場合は、Registry の所有者が表を直接編集して整理してください。

### 1-2. `sources` シート

| 列 | 例 | 意味 |
| --- | --- | --- |
| `sourceId` | `src-m5-01` | 内部 ID。英数字+ハイフン、後から変えにくい |
| `displayName` | `M5 A棟` | ドロップダウンに出る表示名 |
| `schemaType` | `m5stack` / `mechatrax` / `pc-serial` / `remote-ftp` | データ形式 |
| `spreadsheetId` | `1abc...xyz` | 実データのスプレッドシート ID |
| `sheetName` | `soil_sensor` | 実データのタブ名 |
| `allowedSheetNames` | `["sensor_2025"]` | 任意。Proxy が追加で許可するタブ名の JSON 配列 |
| `headerRow` | `1` | ヘッダ行（通常 1） |
| `tz` | `Asia/Tokyo` | タイムゾーン |
| `accessMode` | `direct` / `proxy` | 後述 |
| `enabled` | `TRUE` | `FALSE` で一覧から消える |
| `notes` | （任意） | メモ |

同じ `sourceId` は1行だけ登録してください。前後の空白と大文字・小文字を除いて重複すると、そのソースは閲覧を拒否し、閲覧者の一覧からも除きます。
`sourceId`・`spreadsheetId`・`sheetName`・`enabled`・`schemaType` はそれぞれ1列必要です。
任意の `headerRow`・`allowedSheetNames` も重複させないでください。管理画面からの保存でも確認します。

画面は、`schemaType` が表の4種類以外、`accessMode` が `direct` / `proxy` 以外、
`headerRow` が正の整数以外、`tz` がブラウザーで扱えないタイムゾーンの行を一覧から除きます。
誤記した読み取り方式では直接アクセスしません。未指定時は従来どおり
`headerRow=1`、`accessMode=direct`、`tz=Asia/Tokyo` です。読み込みで設定表を書き換えることはありません。

**`accessMode` の選び方**:

- `proxy` （推奨）: GAS WebApp 経由で読む。Drive 共有は **GAS のオーナー（あなた）1 アカウント** だけで済む。
  代わりに [`04_gas_setup.md`](04_gas_setup.md) の `read_proxy` をデプロイし、`VITE_GAS_PROXY_URL` を設定する必要がある。
- `direct`: Proxy 未設定時のみ、閲覧者ごとの Google アカウントから直接 Sheets API を呼ぶ。
  スプレッドシート全体の閲覧を許可する運用専用で、アプリの ACL は直接アクセスを制限しない。
  位置情報等を含む Mechatrax データには利用できない。

`VITE_GAS_PROXY_URL` を設定すると、`accessMode=direct` の既存ソースも含め、
ダッシュボードは Registry・データ・タブ一覧を Proxy 経由で取得します。拒否時に直接読み取りへ戻りません。
閲覧者には本人・許可ソース・対応レイアウトのみを返し、`notes` は返しません。
`users.enabled` と `sources.enabled` は空欄や `0` でも無効になります。通常は `TRUE` / `FALSE` を使ってください。

### 1-3. `acl` シート

| 列 | 例 | 意味 |
| --- | --- | --- |
| `email` | `prof@example.com` | viewer のメール（admin はここに書かなくてよい） |
| `sourceId` | `src-m5-01` または `*` | 許可する sourceId、または `*` で全許可 |
| `permission` | `read` | 現状 `read` のみ |

`email`・`sourceId` はそれぞれ1列必要です。不足・重複がある場合は閲覧を拒否し、管理画面からの保存も拒否します。
同じメールに複数のソースを許可する行や、`sourceId=*` による全ソース許可は引き続き使えます。

## 2. ワークフロー例（具体的にこう操作する）

### 例A: 新しい viewer ユーザー（教授）に M5Stack 1 個だけ見せたい

前提: 既に `sources` に `src-m5-01` が登録されている。教授のメールは `prof@example.com`。

1. Registry スプレッドシートを開く
2. `users` タブで末尾に 1 行追加:
   - `email = prof@example.com` / `role = viewer` / `enabled = TRUE`
3. `acl` タブで末尾に 1 行追加:
   - `email = prof@example.com` / `sourceId = src-m5-01` / `permission = read`
4. **Proxy が未設定で、`src-m5-01` の `accessMode` が `direct` の場合のみ** 追加で:
   - 実データのスプレッドシート（`src-m5-01` の `spreadsheetId`）を開く
   - 右上「**共有**」→ `prof@example.com` を「**閲覧者**」で追加 → 送信
5. 教授がダッシュボードにログイン → ドロップダウンに `M5 A棟` が出ることを確認

### 例B: 学生数名にすべてのデータを見せたい

1. `users` に学生のメールを `viewer` で複数行追加
2. `acl` で 1 人ずつ `sourceId = *` の行を追加（ワイルドカードで全ソース許可）
3. Proxy 未設定の直接読み取り運用に限り、各スプレッドシートを学生メール全員に「閲覧者」共有。Proxy 利用時は共有しない

### 例C: 一時的にデータソースを非表示にしたい

1. `sources` の該当行の `enabled` を `FALSE` に変える
2. 次の取得・再読み込み時から全ユーザーの一覧に表示されなくなる（admin も対象）。表示済みのデータは自動回収されない
3. 戻すときは `TRUE` に戻す

### 例D: viewer の権限を剥奪したい

選択肢A: `acl` から該当行を削除（特定ソースだけ）
選択肢B: `users` の `enabled` を `FALSE`（ログイン自体を止める）

### 例E: 既存運用中の M5Stack スプレッドシートを取り込む（オンボーディング）

1. ユーザーから「Spreadsheet ID」「タブ名」「列構成」を聞く
2. 列構成が SPEC §4.2 の M5Stack スキーマ（A〜M）と一致しているか確認。
   違えば [`04_gas_setup.md`](04_gas_setup.md) の `addM5StackHeader` で揃える
3. アクセス方式を決める:
   - 各ユーザー個別にスプレッドシートを共有してもよい → `accessMode=direct`
   - Drive 共有を絞りたい → `accessMode=proxy`（read_proxy デプロイ要）
4. ユーザーに依頼して共有してもらう（direct なら全閲覧者、proxy なら GAS オーナーのみ）
5. Registry の `sources` に行を追加
6. 必要な閲覧者を `acl` に追加（例A 参照）

### 例F: ソースを `direct` から `proxy` に切り替える

1. [`04_gas_setup.md`](04_gas_setup.md) で `read_proxy` がデプロイ済みであることを確認
2. `sources` 該当行の `accessMode` を `proxy` に書き換える
3. 各閲覧者の Drive 共有は外して OK（ユーザー側で「アクセス権を削除」）
4. ユーザー（案件主）に依頼して、GAS オーナーのアカウントだけに「閲覧者」共有

## 3. テーマ編集

`/admin` 画面下部のテーマ JSON を編集して保存。

- `chartColors` の数を増やすと自動で循環使用される
- `panels[*]` の `x, y, w, h` で 12 列グリッド上のレイアウトを変更
- `yMin / yMax` で Y 軸スケール固定、`showPoints` で点表示の ON/OFF
- メトリクスキーは正規化スキーマ名（`temperature_c`, `vwc_pct`, `ec_bulk_dsm`, `battery_v` など）

管理画面では、パネル一覧・配置・メトリクス・色などの形式を確認してから保存します。
不正なテーマは保存せず、編集中のJSONを画面に残します。
シートを直接編集した場合も、読み込み時に不正なテーマを既定表示へ戻すか、不正なパネルだけを除きます。

スキーマごとの拡張パネル（M5Stack の RSSI/Error、Mechatrax の外気温・降水・日照・電池残量）は
コード側 (`SCHEMA_EXTRA_PANELS`) で自動付与されるので、`theme` シートには共通パネルだけ書けば OK。

## 4. イベント注釈（`events` シート）

イベント注釈は **各データソースのスプレッドシート** に `events` シートとして配置します（Registry スプレッドシートではありません）。

ヘッダ: `date,label,color,deviceId,enabled,oldDeviceId,newDeviceId`（最後の2列は送信機交換用、既存のイベント行は空欄でよい）

| date | label | color | deviceId | enabled |
| --- | --- | --- | --- | --- |
| `2026-06-25` | `塩処理開始` | `#ef4444` | | `TRUE` |
| `2026-07-01T14:30+09:00` | `センサ再設置` | `#3b82f6` | `6c1` | `TRUE` |
| `2026-07-10` | `全デバイス灌水` | `#22c55e` | `*` | `TRUE` |
| `2026-08-01` | `（非表示メモ）` | | | `FALSE` |

### 列の説明

| 列 | 必須 | 説明 |
| --- | --- | --- |
| `date` | ○ | イベント日時。日付のみ（`2026-06-25`）でも日時（`2026-07-01T14:30+09:00`）でも可 |
| `label` | ○ | グラフ上に表示されるラベルテキスト |
| `color` | | 縦線の色（CSS カラー）。省略時は `#ef4444`（赤） |
| `deviceId` | | 表示対象の制御（下表参照） |
| `enabled` | | `TRUE`（デフォルト）で表示、`FALSE` で非表示。削除せずに一時的に隠したいときに便利 |
| `oldDeviceId` | | 交換前の送信機 ID。交換行のみ入力 |
| `newDeviceId` | | 交換後の送信機 ID。交換行のみ入力 |

### 送信機のみを交換したとき

対象データソースの `events` シートに上記2列を追加し、1回の交換につき1行追加します（FTP、M5Stack、mechatrax 共通）。例: `tohoku-ftp` の `fac` から `1c98` への交換:

| date | label | color | deviceId | enabled | oldDeviceId | newDeviceId |
| --- | --- | --- | --- | --- | --- | --- |
| `2026-09-24 09:00:00+09:00` | `送信機交換` | `#ef4444` | `fac` | `FALSE` | `fac` | `1c98` |

`date` は**交換後の送信機で測定を始めた実際の日時**に置き換え、必ず `+09:00` などのタイムゾーンを付けてください。`enabled=FALSE` でも交換は適用され、縦線・ラベルだけ非表示になります。交換前の新IDの記録はそのまま別系列に残ります。交換後は `fac` の系列に引き継がれます。FTP の `number` や元データは変更されません。次の交換時は `oldDeviceId=1c98`, `newDeviceId=次のID` の行を追加します。

### `deviceId` の指定方法

| 値 | 動作 |
| --- | --- |
| 空欄 | 全チャートに表示（グローバルイベント） |
| `*` | 全チャートに表示（全デバイス明示指定。空欄と同じ効果） |
| デバイスID（例: `6c1`） | そのデバイスのチャートにのみ表示 |

### 補足

- そのデータソースのグラフに縦線で表示される
- 時刻付きにすればセンサ再設置などのピンポイントのイベントも正確に表示可能
- 表示中のデータの時間レンジ外にあるイベントは自動的に非表示になる（横軸が引っ張られない）
- `events` シートが無いソースでは単にイベント注釈が表示されない（エラーにはならない）
- ダッシュボードの設定モーダルからもローカルイベントを追加可能（localStorage に保存、スプレッドシートのイベントとマージ表示）

## 5. カスタムレイアウト（`layouts` シート）

ソースごとに独自のダッシュボードレイアウトを定義できます。
典型例: デバイスごとに列を分けて並べる、バッテリーゲージを表示する、タイトルや設置図を入れる。

### 5-1. `layouts` シートの形式

| sourceId | config | year |
| --- | --- | --- |
| `src-remote-a` | （JSON 文字列。下記参照） | `2025` |
| `src-remote-a` | （翌年の JSON 文字列） | `2026` |

- **A列**: 対象の `sourceId`（`sources` シートと一致させる）
- **B列**: LayoutConfig の JSON 文字列（1セルに全部入れる）。列名は `config` または `json`。閲覧者へ返す際は、JSON 内の `sourceId` と A列が一致し、そのソースの閲覧権限があることを確認する
- **C列**: 対象年（西暦4桁）。空欄は従来どおり全年度共通のレイアウト。対象年があればそちらを優先

年別レイアウトを登録すると年セレクタが現れます。表示中の期間にデータがある最新年を初期選択し、選択年のデータだけを表示します。過去年を選ぶと表示期間もその年の全期間に切り替わります。年をまたぐ期間でも一度に使うレイアウトは1件です。対象年の行が無いときは共通行を使い、共通行も無ければ自動レイアウトを使います。交換後の年の `devices` や `deviceFilter` には新しいaddrを書けます。表示時に交換履歴に従って同じ系列へ解決されます。

### 5-2. LayoutConfig のトップレベル

```json
{
  "sourceId": "src-remote-a",
  "title": "圃場名 2026",
  "cols": 14,
  "rowHeight": 60,
  "bg": "#1a1a1a",
  "surface": "#2a2a2a",
  "textColor": "#ffffff",
  "batteryRanges": [2, 2.5, 3, 3.6],
  "devices": ["6c1", "faa", "1c9f"],
  "deviceLabels": [
    "6c1\nSensor 1: depth 0cm\nSensor 2: depth 5cm",
    "faa\nSensor 1: depth 0cm\nSensor 2: depth 5cm",
    "1c9f\nSensor 1: depth 1cm\nSensor 2: depth 5cm"
  ],
  "panels": [ ... ]
}
```

- `devices`: デバイスアドレスの配列。パネルの `deviceRef` で **インデックス参照** する
- `deviceLabels`: デバイスのラベル配列。text パネルの `contentRef` で参照
- `devices` / `deviceLabels` を使うと、JSON 内でアドレスを何度も書かずにインデックスで参照できる
- `batteryRanges`: 全バッテリーゲージ共通の `[最小値, 黄色開始, 緑色開始, 最大値]`（V）。上記なら赤 2～2.5 V、黄 2.5～3 V、緑 3～3.6 V。省略時は同じ値が既定値
- 特定のゲージだけ変えたい場合は、そのパネルの `ranges` が `batteryRanges` より優先される
- 既存の JSON を共通設定に移す際は、トップレベルに `batteryRanges` を追加し、各ゲージの `ranges` を削除する。残した個別値は共通値より優先される

### 5-3. パネルタイプ

| type | 用途 | 主なフィールド |
| --- | --- | --- |
| `chart` | 折れ線グラフ | `metric`, `deviceRef` or `deviceFilter`, `groupBy`, `groupColors`, `showEvents` |
| `gauge` | 半円ゲージ（バッテリー等） | `deviceRef` or `deviceFilter`, `ranges` |
| `text` | 任意テキスト | `content` or `contentRef`, `fontSize`, `align` |
| `image` | 画像（設置図等） | `src`, `fit` |

**`deviceRef` vs `deviceFilter`**:
- `deviceRef: 0` → `devices[0]` のアドレスに解決される。単一の非負整数を指定する
- `deviceFilter: ["6c1", "1c9f"]` → アドレスを直接指定
- どちらか一方を使う。複数デバイスを指定する場合は `deviceFilter` を使う

**`contentRef`（text パネル）**:
- `contentRef: 0` → `deviceLabels[0]` のテキストを表示

Registry のレイアウトも読み込み時に検査します。不正なパネルや重複IDは除き、正常なパネルを維持します。
パネル一覧がない場合や、非空の一覧がすべて不正な場合はその設定を使わず、後続の正常な設定や既定表示へ戻します。
明示的な空の一覧 `panels: []` は有効です。配置の座標・サイズの範囲は、ブラウザーの保存設定と同じです。
`devices`・`deviceLabels` に不正な要素がある場合は、番号の対応をずらさないようレイアウト全体を使いません。
数値の `fontSize: 24` は従来と同じ24pxとして扱います。文字列のCSSサイズも引き続き使えます。

### 5-4. chart パネルの `groupBy`

- `"deviceId"`（デフォルト）: デバイスごとに線を色分け
- `"sensorNumber"`: 同一デバイス内のセンサ番号（深度）ごとに色分け
  - FTP データの `number` 列に対応。例: `1`=0cm, `2`=5cm, `3`=10cm
  - `groupLabels`: `{"1": "0cm", "2": "5cm", "3": "10cm"}` でラベル変更可
  - `groupColors`: `{"1": "#3b82f6", "2": "#22c55e", "3": "#eab308"}` で色指定可
- `showEvents`: `true`（デフォルト）でイベント注釈縦線を表示

### 5-5. `remote-ftp` ソースの自動レイアウト

`layouts` シートに行が **無い** 場合、`remote-ftp` スキーマのソースは
データに含まれるデバイス一覧から **デバイス列レイアウトを自動生成** します（`generateDeviceColumnLayout()`）。
自動生成されるパネル構成:
- タイトル行
- デバイスごとの列: ヘッダ（ラベル）→ バッテリーゲージ → 温度 → EC → VWC → 気温（あれば）

明示的にカスタムしたい場合のみ `layouts` 行を追加してください。

### 5-6. レイアウト運用例

**ケース**: 7台のセンサがあり、デバイスごとにゲージ＋温度＋EC＋VWC を縦に並べたい

1. Registry スプレッドシートの `layouts` タブを開く（無ければ作成: A1=`sourceId`, B1=`config`, C1=`year`）
2. A2 に `src-remote-a`
3. B2 に JSON を貼り付け（参考: `docs/layout.json` に実例あり）
4. ダッシュボードをリロード → カスタムレイアウトが適用される

> **レスポンシブ**: モバイルブラウザではパネルが 2 カラムに自動スタックされ、ドラッグ・リサイズは無効化されます。

## 7. PII / 取り扱い注意

`mechatrax` の生スプレッドシートには **位置情報・基地局情報・端末識別子** が含まれます。
ダッシュボードのアダプタはこれらを **意図的に読み飛ばす**（`HEADER_MAP` に登録していない）ため、
CSV ダウンロードや画面表示には出てきません。
ただし **生データ自体の Drive 共有範囲** は管理者が適切に絞ること。

## 8. 表示モード（ビューモード）

ダッシュボードには「**編集モード**」と「**表示モード**」の 2 つがあります。
ヘッダー右側の「表示モード」ボタンで切り替えます。

### 編集モード（デフォルト）
- パネルのドラッグ＆リサイズが可能
- テキストパネルのダブルクリック編集、削除ボタン表示
- 「+ テキストボックス」「+ グラフ」ツールバー表示
- 設定・管理リンク表示

### 表示モード
- **印刷・プレゼン向け**のクリーンな見た目
- ドラッグハンドル（⠿）非表示、リサイズ無効
- 編集系 UI（設定ボタン、追加ツールバー、削除ボタン等）非表示
- ブラウザの印刷機能 (`Ctrl+P`) でヘッダーが自動的に非表示
- データソース選択と期間フィルタはそのまま使用可能

> **Tip**: 表示モードで `Ctrl+P`（印刷）すると、ヘッダーが隠れてグラフのみが綺麗に出力されます。

### 保存済み表示設定の復旧

ブラウザーに保存した表示設定が壊れている場合は、不正な項目だけを初期値へ戻すか、不正な一覧要素を除いて表示します。
正常な背景色、表示期間、グラフ、イベントなどは残します。保存済みプリセットを適用する場合や、旧形式の配置を読み込む場合も同じ検査を通します。

配置の座標は0〜10,000、幅と高さは1〜10,000の整数を扱います。この範囲外や小数の配置は、画面の整列処理が応答しなくなることを避けるため復旧の対象になります。
12列を超えるカスタム配置も、この範囲内なら維持します。

復旧の読み取り処理そのものは保存元を書き換えません。次に設定の保存が行われるときに、復旧後の内容が保存されます。

## 9. 困ったときの早見表

| 症状 | 原因の可能性 | 対応 |
| --- | --- | --- |
| ログインできない | `users` に行が無い / `enabled=FALSE` | 行追加 or `TRUE` に |
| ログインできるが何も見えない（viewer） | `acl` に許可行が無い | 例A の手順 3 |
