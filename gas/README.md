# Google Apps Script

v2 では GAS プロジェクトを 3 種類に分けて使う：

## (A) 受信用（データ用スプレッドシートにバインド）

| ファイル | 用途 |
| --- | --- |
| `m5stack_receiver.gs` | M5Stack の POST を受けて A〜M 列に append |
| `mechatrax_receiver.gs` | Mechatrax RasPi の POST を受けて A〜AE 列に append |
| `amedas_fetcher.gs` | mechatrax_receiver から呼ばれる AMeDAS 解決ヘルパ |
| `weather_fetcher.gs` | （旧 v1 互換）Open-Meteo から日次気象を1サイト分取る場合のみ任意で使用 |

Script Properties: `INGEST_TOKEN`（必須）、`M5_TARGET_SHEET` / `MX_TARGET_SHEET`（任意）。

## (B) Registry 用（Registry スプレッドシートにバインド）

| ファイル | 用途 |
| --- | --- |
| `admin_api.gs` | 管理画面からの読み書き API（ID トークン検証 + `ADMIN_ALLOWED_EMAILS` チェック） |
| `read_proxy.gs` | `accessMode=proxy` のデータソース読み出し API |

管理 API と閲覧 API は **別々の GAS プロジェクト**に配置する。
両方が `doPost` を定義しているため、同じプロジェクトの別デプロイでは分離できない。

Script Properties: 両 API に `GOOGLE_OAUTH_CLIENT_ID`（必須）、
スタンドアロン時は `REGISTRY_SPREADSHEET_ID`（必須）。
管理 API には `ADMIN_ALLOWED_EMAILS` も登録し、対象者を Registry の `users` でも有効な `admin` にする。

## (C) アラート送信用（FTP データ用スプレッドシートにバインド）

| ファイル | 用途 |
| --- | --- |
| `alert_mailer.gs` | `alerts` シートを監視し、status=new の行をメールで通知して sent に更新 |

Script Properties: `ALERT_TO`（送信先メールアドレス、カンマ区切り）。
WebApp デプロイは不要。時間ベースのトリガー（5分間隔等）で `processNewAlerts` を呼ぶ。

電池残量低下・測定異常の新規発生・復旧と、継続中の1日1回（JST）の通知はPythonの取り込み処理で判定する。
メールの件名・本文は「新規発生 → 復旧 → 継続中」の順に表示する。
この動作を適用する際は、Pythonと本スクリプトの両方を更新する。シートの列追加やトリガー追加は不要。

## デプロイ

各ファイル群を該当スプレッドシートの GAS プロジェクトに貼り付け、
**「ウェブアプリ」としてデプロイ**（実行: 自分、アクセス: 全員）。

詳細は [`docs/04_gas_setup.md`](../docs/04_gas_setup.md)。

## セキュリティ更新の適用

1. Registry とデータのバックアップを取得する。
2. 管理・閲覧 API を分離し、必要な Script Properties を登録する。
3. 管理・閲覧 API と利用中の各受信 API を更新し、新しいバージョンを WebApp に反映する。
4. `VITE_GAS_PROXY_URL` を設定し、フロントを再ビルドする。URL を変えた場合は対応する変数も更新する。
5. 追加タブが必要なら `sources.allowedSheetNames` に JSON 配列で登録する。FTP の通常タブと `events` は追加設定不要。
6. 一般閲覧者への Registry・生データの Drive 共有を解除し、不要な旧 WebApp デプロイをアーカイブする。
7. 閲覧者・管理者・無効ユーザーで表示と拒否を確認する。

管理 API と管理画面は対応する新しい版をセットで更新する。
古い管理画面からの保存は拒否されるため、更新後は管理画面を開き直す。
Google 側の設定変更・再デプロイ・共有解除は、リポジトリ内のコードを更新しただけでは実行されない。

受信 API と管理 API は新規に書き込む文字列の数式化を防ぐ。
既存セルに保存された不審な数式は自動修復しないため、別途確認する。
管理 API は入力検証後、ロック中の一括書き込みで置き換える。入力不備時に先行して全消去しない。

閲覧 API は受け取る本文を16,384文字までに制限し、超過した場合は JSON の解析や Google への認証照会をせずに拒否する。
これは要求のサイズ制限であり、返す測定行を途中で切り捨てる変更ではない。管理 API の本文上限は従来どおり1,000,000文字とする。
両 API とも、ログインの証明は8,192文字以内の文字列で、3区分からなる基本形式に合うものだけを Google へ照会する。
形式が合っていても、それだけではログインを認めず、Google 側の検証と対象アプリ・有効期限・メール確認を引き続き必要とする。
この対策は不要な照会を減らすもので、GAS の起動自体や正しい形式の大量アクセスを止める回数制限ではない。利用量の監視は引き続き必要となる。

M5Stack・Mechatrax・PC シリアルの各受信 API は、保存先の作成・見出し行や追記位置の確認・書き込み・フィルター更新を同じロック内で実行する。
最大10秒待ってもロックを取得できない場合は、表を変更せず `{"ok":false,"error":"busy"}` を返す。
この場合、送信側で測定値を保持して再送する必要がある。受信 API 自体は再送機能を追加しない。
`request_failed` は保存後の失敗でも返るため、再送前に保存行を確認する。
ロックは同じ GAS プロジェクト内の受信処理を保護するもので、別プロジェクトや Google の表の直接編集までは制御しない。
Mechatrax の天気情報取得はロックの外で行い、取得失敗時も気象列を空欄にして測定値を保存する従来の動作を維持する。

### 何が変わり、何が変わらないか

- 測定値の計算、単位変換、FTP 取り込み、アラート判定、メール送信の処理は変更しない。
- M5Stack・Mechatrax・PC シリアルの受信 API は、予期しない失敗や不正な JSON に対して `{"ok":false,"error":"request_failed"}` を返し、内部の設定情報や送信内容を含む例外文を返信しない。正常時の返信、認証失敗、製造番号の未指定、日時不正の応答は維持する。
- 閲覧時は、見せてよいデータだけをサーバーから返す。未許可のタブや位置情報などは返さない。
- ログインの証明に期限が近づいた場合は通信前に更新する。更新できなければ再ログインを案内する。
- 保存済みログインを復元するときは、ログイン日時が有効で30日以内か、利用者情報の型と認証情報内のメールが一致するかを確認する。日時の欠落・破損・未来の時刻や利用者情報の不整合は再ログインを必要とする。正常な認証更新では最初のログイン日時を延長しない。
- 画面を開いたままでも、認証情報を使う直前と更新完了時に30日の保持期限を確認する。更新を待つ間に期限を過ぎた場合も、初回日時を書き換えて自動延長しない。利用者が新しくログインしたときに保持期間を開始する。
- ログアウト後や保持期限切れの状態では、手元に有効な認証情報が残っていても自動で再利用・更新しない。壊れたログイン応答や無限大になる有効期限も採用しない。通常のログインと有効な認証情報の再利用は維持する。
- ログアウト・別タブでの利用者変更・認証情報の保存失敗によってログインが終了した後は、Sheets を直接読み取る権限も取り直さない。自動更新と利用許可の操作からの要求をともに拒否し、再ログインが成功した後で通常の権限取得を再開する。
- ログアウト・画面終了後に届いた古いログイン応答は採用せず、別タブで新しく保存された認証情報も書き換えない。Google のログイン機能の読み込み待ちは、画面終了時に止める。
- 同じログイン操作の応答は一度だけ処理する。ログイン失敗後や別タブでの利用者変更後も、新しいログイン操作はできる。同時の認証更新はまとめ、返答が来ない場合も待ち続けない。
- ブラウザーの保存領域が使えない場合も、ログアウト時は各項目の削除と Google 側の自動選択解除・トークン取り消しを可能な範囲で続ける。読み取り失敗時は手元の認証情報で継続せず、再ログインを必要とする。ログイン日時の読み取り失敗を未設定とみなして保持期間を延長しない。認証情報の保存失敗はログイン成功として扱わず、待ち続ける状態も残さない。画面には保存設定・空き容量の確認と共有端末での保存データ削除を案内する。
- ログアウト・別アカウントへの切り替えでは共有の表示設定と選択状態を初期化し、古い取得結果や画面終了後の再試行を反映しない。同じ人の認証更新では未保存入力を維持する。端末に保存したアカウント別のダッシュボード設定は削除しない。
- 別タブでのログアウト・認証情報の削除・別アカウントへの変更を通知されたタブは、表示中の画面を閉じて認証更新を中止し、再ログインを案内する。通知を受けた側は、別タブで新しく保存された認証情報を削除したり Google 側で取り消したりしない。同じ人の通常の認証更新や表示設定の変更では、編集中の内容を維持する。
- 別タブからの通知がまだ届いていなくても、使用時や更新完了時に保存済み利用者が変わっていれば古い利用者の処理を止める。その際も別タブの認証情報は削除・上書き・取り消しをしない。
- 利用者が明示的に新しくログインするときは、以前の Sheets 読み取り用認証情報をブラウザーから削除してから保存する。別アカウントの古い認証情報との混在を防ぎ、削除に失敗した場合はログインを完了しない。Google 側の許可は取り消さず、同じ人の通常の認証更新ではこの削除を行わない。
- 設定未保存時・読み込み失敗時・不足項目の補完時の初期値は、読み込みごとに独立して作る。別の利用者や後の読み込みと内部データを共有しない。保存済み設定の削除や保存キーの変更は行わない。
- 表示期間の保存値が不正な場合は、その項目を「直近7日」に戻し、ほかの正常な設定は残す。読み込み後の期間計算でも種類・日付・開始終了の前後関係を確認する。正常な独自期間や全期間表示は維持し、読み込みだけで保存元の設定を書き換えない。
- ブラウザーに保存した表示設定は、配列・各要素・項目ごとの型も確認する。不正なグラフ・テキスト・イベント・配置だけを除き、正常な設定を残す。保存済みプリセットと旧形式の配置も同じ検査を通す。配置の座標は0〜10,000、サイズは1〜10,000の整数とし、整列処理が応答しなくなる極端な値を除く。`toString` などの名前を持つソースでも、継承された値を保存設定と誤認しない。
- Registry のテーマ・レイアウトJSONも読み込み時に形を確認する。不正なパネルを除いて正常なパネルを残し、設定全体が不正な場合は既定表示や後続の正常な設定へ戻す。参照番号を使うデバイス一覧は、不正要素を詰めて別の参照先へ変えない。管理画面では不正なテーマを保存せず、入力内容を残す。読み込み時の復旧はシートを書き換えない。
- Registry のソース一覧は、未対応のデータ形式・読み取り方式、不正なヘッダ行・タイムゾーンを持つ行を画面の読み込み時に除く。読み取り方式の誤記を直接アクセスとして扱わない。未指定時の既定値は維持し、元の設定表は書き換えない。
- パネル・デバイスにも `toString`・`constructor`・`__proto__` などの名前を使える。保存していないテキスト上書き・色・軸設定を継承された値で補わず、これらの名前で明示的に保存した設定は維持する。
- Proxy 利用時はブラウザーからの Sheets 直接読み取りの権限を新たに求めない。過去に Google に与えた許可は自動解除しないため、不要な許可は Google アカウント側で確認する。
- 設定を開いた後で別の操作によって設定が変わっていた場合、古い内容で上書きせず保存を拒否する。
- 管理画面から利用者設定を保存するときは、有効かつ `ADMIN_ALLOWED_EMAILS` に登録された管理者を少なくとも1人残す。Google の表や設定を直接編集する場合には、この保護は働かない。
- `users` の同じメールの重複行は、管理・閲覧 API とも該当者の認証を拒否する。認証に使う `email`・`role`・`enabled` の列もそれぞれ1列だけ必要とする。管理画面からの保存ではこれらの重複を拒否する。既存の重複で操作できない場合は、Registry の所有者が表を直接編集して整理する。
- `sources` の同じ `sourceId` の重複行は、そのソースの閲覧を拒否し閲覧者の一覧からも除く。`sources`・`acl` の認可や対象を決める列が不足・重複している場合も拒否する。管理画面からの保存ではこれらの曖昧な設定を拒否する。正常な列順変更、空白の末尾行、ワイルドカード ACL は維持する。
- 閲覧者向けのレイアウトは `layouts.config` と `layouts.json` の両形式に対応する。行と JSON 内の `sourceId` が一致し、閲覧権限があるものだけを返す。
- 以前選んだ過去年タブが許可されなくなった場合、選択可能な通常タブへ戻す。
- CSV の数値は維持する。数式に見える文字列だけを無害化し、カンマや改行を正しく出力する。その行にない項目は、継承された値で補わず空欄にする。

実際の Google アカウントでのログイン、利用者ごとの閲覧可否、過去データの表示、
長時間利用後の操作、実データ量での応答時間は、本番切替前に確認する。
過去に漏れた情報の回収や、保存済みの不審な数式の修復は自動では行わない。

ブラウザーが削除を拒否した認証情報は、コード側から消せたとは保証できない。
同じ画面ではログアウト済みとして扱うが、開き直すと残った情報が再び読み込まれる可能性がある。
警告が出た共有端末では、ブラウザーの設定からこのサイトの保存データを削除してから端末を離れる。
保存領域の制限や空き容量不足を解消するまでは、ログインを完了できない場合がある。

タブ間の同期は、同じブラウザーの同じサイト内で通知を受け取れる範囲に限る。
別の端末やブラウザーのログインを終了する機能ではなく、すでにサーバーで始まった保存処理も取り消せない。

### FTP の制約

旧式システムとの互換性のため、FTP 通信方式・接続先設定・取り込みコードは変更しない。
認証情報と測定データが通信経路上で保護されないリスクは残り、今回の対策では解消しない。
可能な範囲で専用の読み取り専用アカウント・対象ディレクトリ制限・認証情報の定期交換を行い、
Secrets とサーバーログを管理する。外側のネットワークで通信を隔離できるかも運用側で確認する。
